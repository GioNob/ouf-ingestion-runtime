# R4a managed CSV through the real MCP process

The dedicated workflow reuses R2c's four Java applications, PostgreSQL and MinIO, and adds the real MCP executable. Owner repositories and third-party Actions are pinned to exact commits. Existing R2c acceptance remains separate.

The fixture loads the reviewed 20-field Teatri RDF proposal through real MCP `semantic.propose`, `semantic.review.prepare`, `semantic.approval.request`, followed by the actual HUMAN HTTP card/decision/publication routes and exact MCP semantic resolution/read; authentication alone is an explicit synthetic fixture. It profiles disposable CSV bytes through the real Onboarding profiler, then calls real MCP `source.onboarding.create`, `source.onboarding.review.prepare` and `source.onboarding.read`. A purpose-bound signed test Gateway receipt reaches the actual owner APIs; no test controller substitutes their lifecycle.

The runner confirms and invokes the product HUMAN activation API. The source owner coordinator calls the new Ingestion readiness route, which executes the existing frozen compatibility probe against every CSV row and submits an exact-hash SERVICE attestation. A lost acknowledgment is reconciled from the source owner; probes have a 30-second bound, at most two concurrent attempts and no local retry loop. The source owner retains durable attempts, finite budget and activation fencing, then invokes real UDP identity preflight before activation. The runner does not submit compatibility attestations or identity preflights itself. The production Ingestion activation poller discovers the resulting publication and creates/runs work; the test never inserts an ingestion run or invokes a hidden run trigger.

The baseline contains one 19-field object. The incoming CSV contains the same 19 canonical values plus one newly exposed property and a fully distinct second row. Thus actual complete-canonical-comparison semantics can match the first row to the existing object and commit a new revision, while creating the distinct object. The test verifies object count, retained original identity, both source bindings, increased revision count, three durable handoffs with exact ACK receipt/content-hash reconciliation and authorized lineage from both sources. It finally invokes real MCP `urban.object.search`, checks the exact two unique IDs and complete page, lexical postal code `00123`, the new property and omission of restricted facts.

This is disposable integration qualification. The CSV rows are synthetic; they are not the VPS Teatri asset or its 13 rows. IAM, Gateway mediation, source-byte transport and HUMAN authentication are named fixture boundaries. Chat attachment/picker and browser sign-in have their own tests. Neither a CI PASS nor source publication grants production runtime authority or proves the target deployment.

Each owner is built against its own pinned vendored Authorization SDK. Its runtime and test SDK JARs are retained in a separate classpath directory before another owner can overwrite the shared Maven coordinate. Identity fixtures are excluded from all production artifacts.

The test client spaces tool calls by at least 21 seconds to respect the existing shared business admission limit of three calls per minute. It does not retry rejected calls, alter identities, reset attempts or change server budgets; finite admission and equivalence guards remain active throughout the composed run.
