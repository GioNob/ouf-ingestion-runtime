# Bounded acquisition evidence projection

The deployed operational status/history can report `SUCCEEDED` but cannot prove durable ACK, the pinned managed CSV, or downstream materialization. Add a separate minimized projection for an existing exact source/run. It does not execute an acquisition or claim acceptance.

`POST /api/internal/v1/ingestion/operations/acquisition` accepts only `sourceId`, `runId`, optional `limit` (1–100, default50), and optional `afterLineageId`. Unknown, duplicate, null, coerced and oversized inputs fail before data access. Tenant/source/run are selected together. A short, read-only repeatable-read transaction bounds the query; no network calls, locks, retry, recovery session or mutation are introduced.

All three existing owner permissions are required and reevaluated for the exact source/run and `TENANT_OPERATIONAL`: `ingestion.run.read`, `ingestion.contract.read`, `ingestion.lineage.read`. Metadata admission includes the OPEN label. Every row additionally requires every declared access label under all three permissions; missing/invalid/unpermitted labels redact the row and mark the result partial. A policy48 operational-read grant alone cannot release this projection. Dedicated Gateway receipts must bind the new exact path/capability and contain all three scopes; old status/history receipts cannot be reused. The existing raw historical endpoints remain ineligible for MCP and unchanged.

The report selects run and snapshot bundle identifiers, publication ID and managed content hash, safe opaque handoff/lineage IDs, raw/output hashes, ACK/receipt-presence flags, and property IRIs with NULL/EMPTY_STRING/WHITESPACE_ONLY/VALUE classifications. It never selects CSV values, snapshot configuration as a whole, raw paths, source-object keys, bearer material or raw receipt strings. Per-run attempt/lineage/handoff/quarantine counts are operational metadata. `SUCCEEDED` and ACK are distinct from materialization.

Current source watermark evidence explicitly says whether it belongs to the requested run. Only that run's handoff/sequence can be projected, along with receipt-complete ACK-prefix, candidate equality and commit-after-ACK flags. A later or inconsistent watermark is not rewritten or inferred as historical success. A current snapshot cannot prove past transient ordering or a historical overwritten watermark. Pagination and partition truncation are explicit; pages are separate snapshots, not one durable snapshot across requests. `downstreamMaterializationProven` is always false: UDP must supply its own governed evidence.

This candidate is based on recorded deployed source4165b9e149be467d5d7c6bed35e4e1af4e249db1. No schema migration. No deployment, permission publication, Gateway/MCP binding or E2E acceptance is implied. Qualification uses a disposable PostgreSQL17 instance with synthetic private inputs and actual owner-policy/transaction/query code; it must not be reported as a VPS result. Next steps are source-scoped authorization/transport composition, UDP minimized evidence, then one qualified delivery with concrete human review if target changes are needed. Never repeat either known Teatri acquisition to obtain evidence for the other.

## Isolated owner read entrypoint

`it.comune.trieste.ouf.evidence.IngestionAcquisitionReadApplication` imports only the minimized read and its authenticated owner boundary; it never scans execution packages. Enforced highest-priority settings disable Flyway and SQL initialization even if caller configuration tries to enable them. Every Hikari connection is read-only with autocommit disabled, at most2 connections and no minimum idle pool; unsupported HTTP routes are denied. No generated user/password or new IAM login is needed. The ordinary packaged main remains unchanged. A dedicated entrypoint permits an additive first-class read component without replacing or restarting retained execution workers. Native disposable HTTP tests verify admission, real PostgreSQL write rejection, absent worker/Flyway beans and inaccessible mutation endpoints. Packaged-container launch and target custody still require qualification before delivery.
