# Authenticated Gateway owner boundary for status/history

The existing /api/internal/v1/ingestion/operations/status and /history POST paths and domain read scope remain unchanged. An explicit opt-in profile installs a higher-priority Spring Security chain for only these two paths. It authenticates X-OUF-Ingestion-Read-Receipt, bounded to30seconds and the exact method/path/capability/body hash, verified HUMAN identity and roles/scopes, issuer/audience/workload and correlation/attempt/idempotency values. The HMAC domain is ouf-ingestion-read-owner-v1. A server-created SDK TrustedPrincipal reaches the existing owner policy evaluation; ordinary identity headers, service bearer, missing proof, different tenant or absent grants do not authorize a read. Query strings, wrong methods, oversized bodies and duplicate receipt headers are rejected. No receipt can satisfy HUMAN mutation or other owner endpoints.

The default remains disabled. Enabling requires approved installation bindings OUF_ING_GATEWAY_READ_ENABLED/ISSUER/AUDIENCE/WORKLOAD/KEY_FILE and a separately admitted secret-file reference. The Gateway must use a distinct owner receipt key; never provision the MCP delegation key to Ingestion. The installation profile must describe independent Gateway and owner secret placement without assuming shared filesystem/network. No secret or environment-specific host is a code default. No migrations, new IAM grants, source approval or source activation are part of this patch.

Cross-repository qualification generates actual Lua receipts from Gateway commit6bcb28906eee08e0ebe3507b8b58dd987012c8e6 and passes them through the real Java verifier and MockMvc Spring Security/SDK policy boundary with a public fixture key/fixed clock. Production uses UTC and native installation configuration. Existing IAM/JWT HUMAN paths retain their tests. Disabled-profile rejection is tested separately.

The target JAR58199f4b contains the IAM and disabled-denyAll configurations but its inspected environment does not enable IAM. Disk metadata alone does not prove which chain the live JVM selected or the exact401cause. This patch supplies the missing authenticated delegated READ contract; it does not claim target rollout or milestones5–6.

Normative basis: GatewayPET1.5 T29.7, AuthorizationPET1.5 section4.3, Matrix1.7 section1. No cluster-origin trust or unsigned-header fallback. Runtime enablement, owner secret binding and two Gateway function replacements require a new finite HUMAN review; completed owner/rename/route operations must not be replayed.
