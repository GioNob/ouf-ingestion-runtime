# Ingestion IAM principal boundary

The servlet APIs now accept a independently verified JWT bearer and expose the SDK TrustedPrincipal on the final servlet request. The adapter uses Spring OAuth2 Resource Server / Nimbus JWKS discovery, issuer/timestamp checks, mandatory expiration and configured audience. Client identity/capability headers are ignored by SDK. HUMAN_USER normalizes to HUMAN, conflicting human subject aliases fail, and SERVICE/AI_AGENT require a canonical workload claim; human-only actions remain denied to non-human actors by owner policy. Capabilities, grants, tenant boundaries and resource policy continue to be evaluated locally by the shared authorization SDK.

Deployment bindings: `OUF_ING_IAM_ENABLED=true`, `OUF_ING_IAM_ISSUER=<https IAM issuer>`, `OUF_ING_IAM_AUDIENCE=<gateway API audience>`. Corresponding property keys are `ouf.ingestion.iam.enabled`, `.issuer`, `.audience`. Settings are generic and contain no source or run IDs. Disabled/missing enablement denies protected API namespaces; no generated login and no client-header fallback. Health and outbound worker loops remain separate. No Flyway migration. Keep activation and execution loop settings and existing registry/token mounts during adoption.

The adapter follows the UDP principal bridge already deployed: it runs after SecurityContextHolderAwareRequestFilter so the final controller request returns TrustedPrincipal rather than Spring Authentication. Test JWT decoder in HTTP boundary tests uses a real RSA public-key verifier and production validators; tokens are signed with local test keys. Cases cover good HUMAN, HUMAN_USER, bad signature/issuer/audience/expiry/missing expiry, forged headers, missing scope, other tenant, SERVICE on HUMAN APIs, unknown actor and conflicting subject. These are CI tests, not production authorization evidence.

This change builds on the governed cursor retry correction. Do not resume any production run until exact-commit CI, release/package checks, runtime bindings/adoption, rollback evidence and actual authorized HUMAN GET readbacks pass. The source stays ACTIVE and original PAUSED run remains preserved. Retry remains an explicit HUMAN versioned operation, followed by run resume. S3 and UDP delivery/materialization/search still require live execution proof.
